# 部品とプリセットの案内

[使い方ガイドに戻る](guide.ja.md)

パズル部屋は部品を組み立てて作ります。この文書では、部品が信号でつながるしくみ、プリセットで部屋を組む手順、点検と段階的な学習、そしてすべての部品の値の表を扱います。値の表は`mpg parts --markdown`が出力したもので、それ以外は人が書いた説明です。

## 部品、プリセット、組み立てプリセット

- **部品**は`room.yaml`の`parts:`の一行です。種類(`type`)と値でできています。種類ごとに受け付ける値と単位、既定値、許される範囲が決まっていて(値のスキーマ)、範囲外の値は`mpg build`と`mpg check`が理由と範囲を示して拒否します。
- **部品プリセット**は、部品の種類一つと既定値のセットです。コードはありません。`src/mujoco_puzzle_gym/presets/parts/<分類>/<名前>.yaml`にあり、分類は`input`(ボタン・センサー)、`logic`(ゲート・カウンター・トランシーバー)、`device`(ドア・ワープ・ゴールネット・プラットフォーム・柱・回転台・コンベヤー・スプリング・設定変更器)、`floor`、`trap`、`object`、`beak`、`npc`(自分で動くロボット)です。
- **組み立てプリセット**は、複数の部品をまとめたもの、または部屋一つ全体です。`presets/puzzles/<テーマ>/<名前>.yaml`にあります。

`mpg parts --json`は、登録された部品と値のスキーマ、プリセットの一覧を出します。自作の部品まで見るには`--plugin my_parts`を付けます。

## プリセットで部屋を組む

部品の行に`preset:`を書くと、プリセットの種類と値を取り込み、その行に書いた値がプリセットの値を上書きします。

```yaml
parts:
  - {name: button_a, preset: input/floor_oneshot, pos: [-0.35, 0.55]}
  - {name: door, preset: device/sliding_door, pos: [0.4, 0.0], width: 0.4, in: [button_a]}
```

部屋のいちばん上に`preset:`(名前一つ、またはリスト)を書くと、組み立てプリセットを敷いて、その上に部屋の値を重ねます。

```yaml
preset: puzzles/coins/coin_lock     # コイン3枚、コインロックlock、ドアlock_door
size: [2.4, 1.8]
spawn: {pos: [-0.9, -0.7]}
parts:
  - {name: lock, need: 2}                         # 同じ名前: 値だけ変える
  - {name: goal, type: goal, pos: [0.85, 0.0]}    # 新しい名前: 足す
```

合わせ方の規則は次のとおりです。リストの順に合わせ、部屋のファイルが最後です。

- いちばん上の値(`size`、`spawn`、`demo`など)は、後のものが置き換えます。プリセットの`name`は引き継ぎません。
- `parts`は`name`で突き合わせます。同じ名前の行に`type`か`preset`があれば部品をまるごと置き換え、なければ書いた値だけを変えます。新しい名前は後ろに足します。
- `links`はつなげます。

上書きした値を含む最終的な値は、学習のときに`runs/<id>/task.resolved.yaml`の`room_parts`に残ります。

部屋を組む手順:

1. `mpg parts --markdown`か下の表から、使うプリセットを選びます。
2. 壁と出発点を決め、部品の行ごとに`preset`と`pos`、変える値を書きます。
3. 信号をつなぎます。受け取る部品の`in:`に、送る部品のチャンネル名を書きます。
4. `mpg build`で画像を見て、`mpg check`で点検します。

## 信号バス

部品は名前の付いたチャンネルで信号をやりとりします。

- チャンネルの値は実数です。オン・オフは1と0で、0.5より大きければオンと読みます。カウンターは数えた数をそのまま載せます。
- 部品は`in`のチャンネルを読み、`out`のチャンネルに書きます。`out`を書かなければ、ボタンやゲートのように信号を出す部品は自分の名前のチャンネルに書きます。カウンターは`<名前>.count`、`<名前>.reached`のような、点の付いたチャンネルも出します。
- `enable: <チャンネル>`がオフのとき、その部品の出力は止まります(電源)。
- 体のステップごとに、入力部品 → 論理部品 → 装置部品の順に一度ずつ更新するので、ボタンからドアまで同じステップで伝わります。
- 状態を持たない部品だけで回るループ(NOT → NOT)は拒否します。遅延やラッチのように状態を持つ部品をはさんだループは使えます。
- M1の`links: [{from, to}]`は、受け取る部品の`in`に送る部品のチャンネルを足すのと同じです。

## 式ゲートの文法

`type: gate`は、次のどれか一つで出力を計算します。

- `expr`: チャンネルを読む式。例: `a and not b`、`delay(btn, 1.5)`、`latch(pulse(a), reset_btn)`、`count(lap) >= 3 or timer(plate) > 2`。
- `op`と`in`: チャンネル名を式に書かない形なので、プリセットで使います(`logic/and`など)。`and`、`or`、`xor`はすべての入力、`not`、`delay`、`hold`、`pulse`、`timer`、`count`は入力一つ、`latch`は`[set, reset]`です。
- `sequence: [a, b, c]`: 順序ロック。順序を間違えると`<名前>.wrong`が1ステップだけオンになります。
- `logic: <名前>`: `register_logic`で登録したPython関数。

式で使えるもの: チャンネル名(点の入った`laps.count`もチャンネル一つ)、数値、`and or not xor`、比較(`< <= > >= == !=`)、かっこ、関数`delay(x, s)`、`hold(x, s)`、`pulse(x)`、`latch(set, reset)`、`count(x)`、`timer(x)`。算術、属性アクセス、ほかの関数の呼び出し、文字列は、部屋を読み込むときに拒否します。式は`ast`で読んで許可リストと照らし合わせ、このパッケージが自分で計算するので、他人が作った部屋のファイルを開いてもコードは実行されません。

## 信号機と論理部品の本体

`type: source` は部屋に置かれる箱で、自分のチャンネルに毎ボディステップ値を送ります。ボタンがなくても回路が動くようにする部品です。

- 方式は四つ: `const`(`value` を固定)、`clock`(`period` ごとに `duty` の割合だけオン、`phase` でずらす)、`pattern`(`pattern` の値を `step` 秒ごとに順番に、繰り返し)、`random`(`low`〜`high` の値を `hold` 秒ごとに引き直す)。
- `enable` がオフのときは `off_value`(既定 0)を書き、時計は止まります。止まっている間は時間が進まないので、再びオンにすると止まった位相から続きます。
- `random` は部品名と `seed` で決まるので、同じ部屋なら毎エピソード同じ数列です(`demo:` の解答と `mpg check` が再現します)。エピソードごとに変えたいときはランダム化(R35)を使います。
- チェックポイントの保存には時計・パターンの位相と乱数の状態が入るので、復元しても周期が最初からやり直しになりません。
- プリセット: `logic/source_const`、`logic/source_clock`、`logic/source_pattern`。

`body: true` を与えるとゲート・カウンター・信号機が部屋の中に小さな箱として置かれます(信号機は既定で置かれます)。

- 箱の上のランプが現在の値を見せるので、信号がどこから来るのかが絵で分かります。
- 箱は衝突します。歩く本体は 1 cm の段差までしか越えられないため、箱は壁のように道をふさぎ、部品が自分の底面を知らせて経路探索と `demo:` 実行器が箱を回り込みます。
- ふさがれる場所はくちばしでつつくためにも必要です。歩行方針は命令 0 でも前に流れ、後ろに歩けないので、何もない床では止まって立てません。
- 大きさは `size`(底面 [x, y])と `height` で決めます。

## 配線と破壊

`type: wire`は、チャンネル一つ（`carries`）を`to`に書いた部品へ運ぶ、目に見えるケーブルです。切ると**その部品だけ**がチャンネルの代わりに`broken_value`（既定0）を読みます。同じチャンネルを読む他の部品はそのままなので、配線は「二つ目のチャンネル」ではなく部屋の中の場所です。

- `to`の項目は`<部品>`（その部品が`carries`を読むすべて）または`<部品>.<チャンネル>`です。端は固定部品にだけ置きます。押して動かせる部品（`movable: true`）につなぐと`mpg check`が拒否し、その接続はトランシーバ（R8）で行います。
- ケーブルは`pos`から`path`の点をたどって床に敷かれ、衝突しません。マーカー（R26）はケーブルではなく札板に付きます。
- `breakable: true`でケーブルカバーが付きます。カバーは弾と物体だけが衝突し、アヒルとは衝突しません（アヒルの各ボディを除外します）。
- つついて切る配線は、カバーを壁（`mount: wall`、`pos`は壁面の点、`facing`はアヒルが来る側）か、アヒルを塞ぐ部品（`mount: part`、`on: <部品>`）に付けます。壁面から`depth` 0.04 m出て`height` 0.18 mまで届き、つつき判定は0.02 mです（計測値）。アヒルは何もない床では止まって立てないので、塞がれる場所でなければなりません。
- プリセット: `logic/wire`（絵だけ）、`logic/wire_cut`（壁付きのつついて切る配線）。

`breakable: true`は本体のある回路部品（信号機、`body: true`のゲートやカウンタ、配線、中継器）に付けられ、`by`に書いた原因だけを数えます。

| 原因 | 数える条件 |
|---|---|
| `shell` | 大砲の弾（R16）が`min_speed`以上で当たる。弾一つの接触一回は一度だけ数えます。 |
| `crush` | 物体（R17/R28）が落ちる、または押しつけられて接触力が`crush_force`（既定0.5 N）以上。物体一つの接触は一度だけ数えるので、載っているだけの物体が毎ステップ体力を削りません。弾は数えません。 |
| `peck` | くちばし先端が`peck_dist`（既定0.02 m）以内にある状態でつかみをオンオフする。 |
| `destroyer` | 破壊器が叩く。 |

- `hp`回当たると壊れ、出力が`broken_value`で固定され`<名前>.broken`がオンになり、形が変わります（切れたカバーは暗くなり衝突しなくなります）。残りは`<名前>.hp`で見ます。
- `on_break: fail`は壊すとエピソードが失敗で終わります（切ってはいけない配線）。
- `repair`チャンネルがオンの間は元に戻り、`hp`も最初の値に戻ります。ヒューズで直す道は、ソケット（R5 `receptacle`）がそのチャンネルを書くようにすることです。
- 壊れた状態と残り体力はチェックポイントの保存に入り、復元やリセットのあとに形を入れ直します。
- 計測値（条件ごとにシード20個）: 30 gのキューブを5 cm落とすと0.87 N、アヒルが押しつけると2.6〜12.2 N、ただ載せると0.30 Nです。そのため既定値は0.5 Nです。約51 gより重い物体は載せるだけで壊すので、`mpg check`がそのような部屋を警告します。

`type: relay`は受けたチャンネルをそのまま出す箱です。切る地点を部屋に置くために使います。

- 既定で本体があります。`movable: true`なら自由関節の箱で押せ、`hitch: true`なら綱（R31）を掛けて引けます（プレスの下へ引いてくるパズル）。
- プリセット: `logic/relay`。

`type: destroyer`は`in`がオンになるたび一回叩くハンマーやプレスです。

- `targets`を書けばその部品だけ、書かなければ`size`の範囲にある壊せる部品を叩きます。`cooldown`は叩く間隔、`charges`は使用回数（無記入なら無制限）で、残りは`<名前>.charges`で見ます。
- 壊せる部品にだけ作用します。ハンマーは形だけなので、アヒルや物体は真下にいても力を受けません。
- プリセット: `device/destroyer`。

観測項目`circuit`は、壊せる部品ごとに相対位置と破壊の有無を返します（部品あたり3個）。

ヒューズで直すには`repair_with: <マーカー番号>`を与えます。その番号を持つ物体（R26マーカー）が部品から`socket_dist`（既定0.06 m）以内に置かれるとソケットに差したものとみなし、部品は元に戻ります。0.2 mの箱の上にくちばしの届く面はないので、くちばしは部品の横に置きます。`repair`チャンネルと`repair_with`はどちらか一方あれば十分です。

`mpg check`の`circuit`段階（破壊グラフ）

- 部品が壊れると読む値が変わる部品をたどり（`circuit.py`）、部品ごとに「届く部品」と「消えるチャンネル」を出します。結果にそのまま入るので、部屋を作るときにグラフが何を知っているか読めます。配線は`to`の読み手だけが変わり、チャンネル自体は生きています。
- 失敗: `demo:`が`on_break: fail`の部品を壊すとき、または壊しても何も読んでいない部品を壊すとき。
- 警告: 直す手段（`repair`、`repair_with`）がない部品の破壊で、解答が通る扉が閉まるとき（計画に破壊を入れて判定します）。原因ごとの警告は`parts`段階にあります: `shell`なのに部屋に大砲がない、`peck`なのにアヒルを止める場所ではない（壁や塞いでくれる部品の胴に付いていない）、`crush`なのにその部品の上に載せられる物体の重さが`crush_force`を超える。
- 計画（R6a）: `demo:`が壊す部品は最初から壊れているものとして扱い、順序からは外します。壊すことは歩いて行く場所ではなく、切らなければ開かない部屋もあるからです。

解答の下位目標`break <部品> via <shell|crush|peck|destroyer>`と`repair <部品>`

- `peck`: カバーが向いている側の0.3 m手前まで道を探して行き、体で寄りかかって頭を下げ、環境ステップごとに掴みを入れて切ります。歩いて寄ったアヒルのくちばしは壁のカバーから1.4〜2.2 cm、床に立つ箱から4.4 cm離れて止まるので（2026-11-14測定）、プリセットは`peck_dist`を0.04 m（カバー）と0.06 m（箱）にしています。taskに`head`と`grab`が必要です。
- `shell`: 大砲の照準チャンネルのマスごとに弾道を計算して部品の面に当たるマスを探し、レバーまで道を探して行ってそのマスまで押し、発射ボタンを踏みます。
- `crush`: 物体を掴んで部品の上に落とします（そっと置くだけでは0.30 Nで壊れません）。taskに`head`と`grab`が必要です。
- `destroyer`: その部品を叩くプレスの`in`を書くスイッチを押します。
- `repair`: `repair_with`があればその番号のヒューズを掴んで部品の横に置き、なければ`repair`チャンネルを書くスイッチを押します。
- 壊した後・直した後は部品から0.35 m離れるまで下がります（最大3秒）。部品の箱に寄りかかったままの体は計画が塞がったマスと見るので、次の下位目標がその場で止まります。

プリセット`puzzles/circuit/`8種と例の部屋`examples/rooms/power_cut.yaml`

| プリセット | 解き方 |
|---|---|
| `cut_the_lock` | 信号源 → 配線 → 中継器 → 錠。大砲で中継器を壊すと扉が開きます。 |
| `wrong_wire` | 配線2本。マーカー1をつついて切れば開き、マーカー9（`on_break: fail`）を切ると失敗です。 |
| `fuse_repair` | プレスが最初のステップで中継器を壊します。ディスペンサーからヒューズを取って差します。 |
| `clock_door` | 時計の信号源で開閉する扉のタイミングを合わせて通ります（壊さない基本の部屋）。 |
| `press_relay` | ボタンでプレスを下ろして中継器を壊します。 |
| `jam_the_turret` | 横風を回す信号源をつついて壊し、道を静かにします。 |
| `peck_cable` | 壁のケーブルカバーを2回つついて切ります。 |
| `sabotage_order` | 中継器2つをa → bの順で壊します。順序を間違えると`lock.wrong`のパルスが両方を直します。 |

- 測定値（2026-11-14、`mpg check`、シード20個）: 8種すべて20/20。`power_cut.yaml`は20/20（平均50.5秒、エピソード120秒）で、時計の扉 → 大砲で中継器を切る → ヒューズを差す、の3部屋を通ります。時計の扉が通行中に閉まるとアヒルが戸口で曲がって倒れるため（17/20、次に13/20）、開いている時間を10秒の60%にして20/20になりました。
- `crush`を使うプリセットはありません。原因は試験で確認します（40 gのディスペンサーキューブを低い中継器に落として4/4）。

## 動く装置と設定変更器

- プラットフォーム(`platform`、プリセット`device/moving_platform`、`device/elevator`): `pos`から測った`path: [[dx, dy, z], …]`(zは上面の高さ)を`speed`でたどります。`mode`は`loop`、`pingpong`、`once`、`run`は`always`、`while_signal`(信号がオンの間)、`on_signal`(オンになるたびに一回運行)です。スライド関節と位置アクチュエーターで動くので、上に置いた物体も一緒に運びます。
- 昇降柱(`pillar`)、回転台(`turntable`)、コンベヤー(`conveyor`): 信号がオンの間、せり上がり、回り、ベルトの上の体と物体をベルトの速さで運びます。コンベヤーのベルトは床に描いたものなので、摩擦は床と同じです。
- 低い棒(`low_bar`、プリセット`device/low_bar`): 道を横切る固定の棒です。かがんだ車輪のアヒルだけが下をくぐれます。下の[アドオンステーション](#アドオンステーション)。
- スプリング(`spring`、プリセット`device/spring_pad`): パッドの上の対象に速度`velocity` [vx, vy, vz]を与えます。プリセットは物体だけを飛ばします(`trigger: object`)。
- 設定変更器(`setter`): 信号がオンになった瞬間に`target: <部品>.<値>`を`value`に変え、`revert: true`ならオフになったときに元に戻します。下の値の表で「実行中の変更」が「可」の値だけが対象になります。ドアの幅のような大きさの値は、部屋を読み込むときに拒否します。
- 値の連結`bind`: すべての部品が受け取る値です。`bind: {speed: {from: lever.angle, map: [-1, 1, 0, 0.3]}}`のように、実行中に変えられる数値をチャンネルに直線でつなぎ、体のステップごとに値の範囲で切って適用します。同じ値を`bind`と設定変更器の両方が変える場合は拒否します。
- 解の順序と解答は、プラットフォームと回転台のマス、せり上がる柱のマスを避けて進みます。体が乗ったまま耐えられるかは歩行ポリシーが学んだ範囲の外なので、記録だけを取ります。2026-11-12の記録: プラットフォーム0.1・0.3 m/s、ベルト0.1・0.2 m/sで3秒間転びませんでした。

## 罠

罠(`trap`分類)は体を押したり、倒したり、落としたりします。どれも`in`の信号がオンの間だけ動き(`in`がなければ常に)、強さは`power`一つで決めます。`enabled: 0`で止まります(`in`のない穴は常に開いていて止められず、`enable`や`enabled`を書くと拒否します。切り替えるには`in`を与えます)。`power`と`enabled`は実行中に変えられるので、設定変更器、`bind`、難易度段階(後述)で調整します。

| 罠 | プリセット | `power` |
|---|---|---|
| 風 `wind` | `trap/crosswind` | 区域内の体と物体を押す力 [N]、向きは`yaw` |
| 押し板 `pusher` | `trap/pusher` | 板が箱から出て戻る速さ [m/s] |
| 回転バー `spinner` | `trap/spinning_bar` | 床の高さのバーの回転速度 [deg/s] |
| 振り子 `pendulum` | `trap/pendulum` | 振れ幅 [deg]、周期は`period` |
| 穴 `pit` | `trap/pit` | なし。落ちると`on_fall: fail`(エピソード失敗)か`reset`(出発点かチェックポイントへ)。`in`があるとオフの間はふたが閉じています。`depth`(0.06–0.45 m)を付けるとその深さに底板ができ、合うキューブが板の上に平らに(傾き5°以下、上面が床の高さ±1 cm)収まっている間、そのマスは床です(落下の高さと計画)。キューブが離れるとまた穴です |
| 大砲 `cannon` | `trap/cannon`, `trap/cannon_turret` | 砲弾を撃ち出す速さ [m/s] |
| 滑る床、粘つく床 | `trap/slippery_floor`, `trap/sticky_floor` | 床タイル(`floor_tile`)の摩擦 |
| ブレーキ帯 `brake_strip` | `trap/brake_strip` | なし。体が帯の上にいる間、車輪関節の`frictionloss`(既定0.01 N m)と`damping`(既定0)。下の[アドオンステーション](#アドオンステーション) |

- 解く順序と解答スクリプトは、穴、回転バーと振り子が掃く範囲、押し板が出る範囲を穴とみなして回り込みます。
- 大砲は`period`秒ごとに`burst`発撃ちます(`fire: edge`なら信号がオンになるたびに)。狙い`aim`は`fixed`(`yaw` + `aim_yaw`、`aim_pitch`)、`at_body`(今の体の位置)、`lead`(体が向かう先)、`signal`(`aim_yaw`と`aim_pitch`を`bind`でチャンネルにつなぐ)です。`spread`は狙いの周りの円錐の半角です。`<名前>.fired`は撃った瞬間に1ステップだけオン、`<名前>.hits`は体に当たった数です。
- 砲弾は前もって作った`pool`個(既定10)を使い回します。`lifetime`秒たつか、全部出ていれば一番古いものを回収して撃ち直します。スナップショットには飛んでいる砲弾も入ります。
- 砲弾はボタン、圧力板、区域を押しません。数えるのは的(`input/target`)だけです。的は`min_speed`以上で当たると`<名前>.hits`を増やしてオンになります(`mode: latch`はオンのまま、`pulse`は1ステップ)。
- 砲台(`trap/cannon_turret`)はレバーのような信号で狙い、信号がオンになった瞬間に一発撃ちます。`mpg check`は`bind`が出せる狙いの範囲全体で放物線を計算し、一方向でも的の板に当たれば通します。`spread`があれば円錐全体が板に入る必要があります。
- 倒れる強さの記録(2026-11-12、立っている体、距離0.4 m、横と前から各3回):砲弾の質量 × 速さが0.5 N·s以下では一度も倒れず、0.6 N·s(0.1 kg、6 m/s、前)から倒れはじめ、0.8 N·s(0.2 kg、4 m/s)では6回中4回、1.0 N·s(0.2 kg、5 m/s)では6回とも倒れました。そのため既定値は0.2 kg、5 m/sです。歩いている体はもっと弱く、0.4 N·sの砲弾を2.5秒ごとに受けた解答スクリプトは20回中6回倒れました。
- 砲弾の質量(`shell_mass`)は部屋を組むときだけ決めます。MuJoCoが物体の質量行列を前もって計算しておくため、実行中に変えると動きが狂います。

## NPCロボット

`npc`分類は、自分で床を滑って動く小さなロボットです(`type: npc`)。平面の関節3つ(x、yのスライド、zの回転)と速度アクチュエーターで動き、質量があるので体・物・壁とぶつかります。床のボタンとゾーンは、ロボットの中心を物と同じように見ます(`trigger: npc`か`any`)。上下の関節がなく床に重さがかからないので、圧力板は中心が板の上にある間、ロボットの`mass`を数えます。上にマーカーが付きます。

| 行動`behavior` | プリセット | すること |
|---|---|---|
| `flee` | `npc/flee` | 体が`sense`の中に来ると反対側へ逃げます。ふさがれると壁に沿って滑ります |
| `follow` | `npc/follow` | `sense`の中の体のほうへ来て、`keep`だけ離れて止まります |
| `lure` | `npc/lure` | 体が`bait`の物(キューブ)をくわえている間、その物の方へ来て`keep`だけ離れて止まります |
| `patrol` | `npc/patrol` | `path`(`pos`から測った点、一周)を回ります。体が前をふさぐと止まって待ちます |
| `guard` | `npc/guard` | 持ち場(`pos`)を守り、体が`sense + reach`の中に来ると`reach`まで出てきて立ちふさがります |
| `shy_gaze` | `npc/shy_gaze` | 体がマーカーを見ている間(視線センサー、部屋の`gaze:`)は止まり、見ていないと体のほうへ近づきます。`invert: true`で逆になります |
| `seek_button` | `npc/seek_button` | `in`がオンになると`button`の部品の上へ行って止まります |
| `sleepy` | `npc/sleepy` | `awake`秒のあいだ`path`を回り、`asleep`秒のあいだ止まるのを繰り返します |

- 共通の値: `speed`(最高速度、既定0.08 m/s)、`accel`、`sense`(感知半径)、`size`、`mass`、`leash: [x0, y0, x1, y1]`(ロボットの中心が出ない箱、部屋の座標)。`enable`がオフになるとその場で止まります。`speed`、`accel`、`sense`、`keep`、`reach`、`awake`、`asleep`は実行中に変えられます。
- 壁の回避: 進みたい方向とその±35°、±70°に光線を5本撃ち、ふさがれていない最初の方向へ進みます。5本ともふさがれると止まります。規則に乱数がないので、同じシードなら同じ軌跡です。
- チャンネル: `<名前>.moving`(動いている間1)、`<名前>.on`(乗っているボタンのマーカー番号、なければ-1)。観測項目`npcs`は、ロボットごとの相対位置、速度、動いているか、反応中か(6個)です。
- `speed`が体の歩く速さ(約0.16 m/s)以上だと、`mpg check`の`parts`段階が警告します(失敗にはなりません)。体が追いつけないためです。
- `seek_button`のロボットの`button`(ロボットが押せるボタン、ゾーン、レーザー、圧力板)は、解く順序ではロボットの`in`がオンになればオンとして数えます(`in`がなければ最初から)。体はその上へは行かず、ロボットが行って押します。そのため「スイッチA → ロボット(`in: [A]`) → 板 → ドア」の部屋はAを押すだけで解けます。
- そのほかロボットだけが押す入力(`trigger: npc`、`objects`の指定なし)は、追い込めるロボット(`flee`、`follow`、えさがキューブの`lure`)の`leash`の中(`leash`がなければどこでも)にあれば、解く順序では踏み板として数えます。解答の`demo:`に`herd <ロボット> <部品>`(または`herd <ロボット> <x> <y>`)を書くと、`flee`のロボットは反対側から追い込み、`follow`のロボットは先に立って連れて行きます。`lure`のロボットは、先に`grab <えさ>`でえさをくわえてから`herd`を書くと、くわえたえさで連れて行きます。

## 点検の二段階

`mpg check room.yaml`は、静的段階(シミュレーションなし)と動的段階に分かれます。結果の`static.failed`、`dynamic.failed`が、失敗した段階を順に出します。

静的段階:

| 段階 | 見るもの |
|---|---|
| `values` | 値がスキーマの範囲内か、プリセット名が存在するか、マーカー番号 |
| `channels` | 誰も書かないチャンネルを読んでいないか、一つのチャンネルに書く部品が二つないか、状態を持たないループ、存在しない部品を指すリンク |
| `demo` | `demo:`のサブゴールの命令と対象 |
| `body` | 部品の`requires_body`の能力が体にあるか |
| `parts` | 部品ごとの点検(ゴールネットの入口より大きいボール、届かないボール・コイン)。体と同じくらい速いNPCロボットは警告(`warnings`)だけで、失敗にはなりません |
| `overlap` | 既定の配置で、部品の硬い本体が壁やほかの部品に5 mmを超えてめり込んでいないか。床パッド・旗・ゴール領域は除き、ドアは自分の壁(ドアがふさぐすき間の壁、同じ線上の壁)とだけは重なってもかまいません |
| `order` | 信号と壁から見て、ゴールまでの解く順序があるか。文字マップの部屋では、部品が床のマスの上にあるかと、行く手をふさぐ段差・坂も |
| `actions` | 解くのに要る行動がtaskの`actions`にあるか。物を運ぶか取っ手の装置を操作する必要があれば(`demo:`の`grab`・`pull`、解く順序につかめる物だけが入れられる入力、取っ手の装置)`grab`、解答が押す壁のボタンの板の上端が頭を上げたくちばしの先(0.21 m)より低ければ`head`が要ります |

最初の三段階(`values`、`channels`、`demo`)は部屋を読み込む途中で失敗するので、そのときの結果には失敗した段階だけがあり、解答段階は飛ばします。静的段階だけを見るには`--static`を付けます。

動的段階:

| 段階 | 見るもの |
|---|---|
| `stability` | 指令0で10秒間、転んだり計算が発散したりしないか |
| `solver` | 答えを知っているスクリプトが、ランダム配置20個のうち18個以上を解けるか。部屋に`demo:`(`goto`、`press`、`wait`、`push <ボール> to <ゴールネット>`、`herd <ロボット> <部品>`、`turn <レバーかダイヤル> <値>`、`pull <ひもか引き出し>`、`look <部品>`、`take <ディスペンサー>`、`addon <ステーション>`)があればその順序に先に従い、残りは格子の解答が引き継ぎます |

解答段階は、通った旗ごとにスナップショットを`runs/check/<部屋>/checkpoints/<旗>.pkl`に残します。

## チェックポイントと段階的な学習

旗(`input/checkpoint_flag`、`order: 1, 2, …`)がある部屋は区間に分かれます。まず`mpg check`で旗のスナップショットを作り、`mpg train --curriculum forward`で区間を一つずつ開きます。詳しい使い方は[使い方ガイドの段階的な学習](guide.ja.md#段階的な学習と区間の評価)にあります。

```bash
mpg check examples/rooms/four_flags.yaml
mpg train task.yaml --minutes 60 --curriculum forward
mpg eval runs/<id> --full --segments
```

### 難易度段階

`task.yaml`の`difficulty:`は、罠の強さのような値を段階的に上げます。実行中に変えられる値(「可」)かエピソード開始時に変えられる値だけが対象です。

```yaml
difficulty:
  - {param: cannon_a.power, from: 2.0, to: 5.0, steps: 4}   # 段階0..3で2, 3, 4, 5
  - {param: wind_a.enabled, from: 0, to: 1, at_step: 2}      # 段階2からオン
curriculum: {mode: forward, order: difficulty_first}
```

- `steps: n`は`from`から`to`までをn段階に分け、`at_step: k`は段階kから`to`になります。行ごとに段階数が違えば一番長いものに合わせ、短い行は最後の値のままです。
- 段階的な学習は(区間、難易度)の組を一つずつ開きます。`order: difficulty_first`(既定)は一つの区間の難易度を上げきってから次の区間へ、`segment_first`は一つの難易度ですべての区間を開いてから次の難易度へ進みます。レベル名は`<区間>@d<段階>`で、`curriculum.json`とエピソード記録に残ります。
- `bind`がかかっている値、範囲外の値、大きさの値は部屋を読むときに拒否します。
- 抽選なしで動かすと(評価、ただの`reset`)最後の段階です。`mpg eval runs/<id> --difficulty 1`のように段階を選べます。

### エピソードのランダム化

部屋は何がどこまで変わりうるか(`randomize:`)を書き、`task.yaml`はその範囲を今回の学習でどれだけ使うかを決めます。同じ部屋を固定でもランダムでも学習できます。

```yaml
parts:
  - name: switch_a
    preset: input/floor_momentary
    pos: [-0.6, 0.5]
    randomize:
      pos: {region: [[-1.2, 0.0, -0.9, 0.9]], min_gap: 0.2}
  - name: goal
    type: goal
    pos: [1.1, 0.0]
    randomize:
      pos: {candidates: [[1.1, 0.0], [1.1, 0.5]], weights: [2, 1], holdout: [[0.9, -0.5]]}
  - name: fan
    preset: trap/crosswind
    pos: [-1.0, -0.65]
    randomize:
      power: {range: 0.5, holdout_scale: 2.0}
spawn: {pos: [-1.2, 0.0], randomize: {pos: {range: [0.1, 0.2]}, yaw: {range: 1.0}}}
max_resample: 20
```

```yaml
randomize: {layout: 1.0, physics: 0.5, body: 1.0}   # task.yaml
```

- 引き方は三つです。`range`(基準値±。M1の`random: [dx, dy]`はこの省略形で、両方書くと拒否します)、`region`(箱の並びの中のどこか。`min_gap`で壁や他の部品との間隔を保ちます)、`candidates`(候補から一つ。`weights`も使えます)。`pos`は位置で、それ以外の名前は実行中かエピソード開始時に変えられる部品の値です。
- 層は、位置と開始姿勢が`layout`、部品の値が`physics`、観測の雑音が`body`です。taskの数は部屋の範囲を何倍使うかで、0なら基準値に固定します。既定は1.0なので、部屋に書けば有効になります。実験部屋の引きは`rooms`層です。`look`はまだ無く、0以外を与えると拒否します。
- 同じ値を`bind`や難易度段階も動かす場合は拒否します(どちらかが黙って消えるためです)。
- 引いた部屋が解けない場合(目標の順序が無い、`min_gap`が壊れる、部品が引かれた値を拒否する)は捨てて引き直します(`max_resample`、既定20)。`mpg check`の`resample`段階は種100個で部屋を引き、捨てた割合が30%を超えると警告し、上限まで解ける部屋が見つからない種があれば拒否します。
- 評価専用の値は、`candidates`なら`holdout:`、`region`なら`holdout_region:`、`range`なら範囲の外側の帯(`holdout_scale`、既定1.5倍)です。`reset(options={"randomize": "wide"})`はそれだけを引き(評価専用の値が無い引き方は基準値のままです)、部屋に一つも無ければ拒否します。`"nominal"`は何も引きません。
- 観測項目`randomized`(既定はオフ)は、引かれた部品の値を部屋が書いた範囲で割った数です。`info["draws"]`はそのエピソードが何回引いたかです。
- 連結のシャッフル: 部屋の`randomize: {shuffle: [...]}`は位置と配線を変えます。`{places: [a, b, c]}`は同じ種類の部品同士で位置を入れ替え(どれも自分の位置を引けません)、`{links: <受ける部品>, from: [a, b, c]}`はその部品が今回のエピソードで誰のチャンネルを読むかを引きます(部屋のファイルが候補の一つをつないでおく必要があり、それが基準の配線です)。リセットごとにバスを配線し直すので、計画と手本の解答は引かれた配線を見ます。信号の輪になる配線はその引きごと捨てます。
- 手がかり: 連結のシャッフルに出る部品は床に薄い手がかり板を敷き、つながった二つ(受ける部品と引かれた出力元)だけをその項目の色で塗ります。板の大きさは常に同じなので、色だけが手がかりです。観測項目`part_links`が同じことをワンホットで返します。`hidden: true`なら板はすべて消灯色で観測も0になり、`mpg check`が「記憶か探索が必要で成功率に上限がある」と警告します。
- 観測項目`part_used`は部品の枠ごとに、今回のエピソードで部屋にあるか(1)外してあるか(0)を表します。
- 種類と数: 部品に`randomize: {type: {candidates: [...]}}`を書くとその場所に来る部品の種類を引き、`randomize: {count: [lo, hi], pos: {candidates: [[x, y], ...]}}`を書くとその場所のいくつを埋めるかを引きます。MuJoCoは実行中に本体を追加できないので、候補と複製は部屋を読むときに全部作り(名前は`<名前>#k`)、引かれなかったものは**保管棚**(部屋の外、+x方向)へ片付けます。片付けられた部品は衝突も更新もチャンネルも止まり、計画と観測からも外れます。種類グループの名前を読んでいた部品は、リセットごとに引かれた候補を読むよう配線し直します。数のグループは複製が`hi`個で、場所はそれより多くてもよく(引きが選びます)、基準の部屋は最初の候補と`lo`個です。
- 拒否: 部屋の形そのものである部品(壁の隙間を閉じるドア、壁に付いた板、床のタイル)は片付けると穴が残るのでグループに入れられません。数のグループのチャンネルを読む部品があると、どの複製か言えないので拒否します。評価専用の候補は部屋の`randomize: {holdout: {<グループ>: [<候補>]}}`に書き、学習の引きから外れます(数のグループにはありません)。
- 観測項目`part_group`はグループごとに候補と複製それぞれ1ビットで、部屋にあるものが1です。
- 実験部屋: 部屋単位の`randomize: {rooms: {candidates: [<部屋ファイル>, ...], holdout: [<部屋名>]}}`を書くと、エピソードごとにどの部屋で行うかを引きます。候補は部屋を読むときに全て一つのモデルの離れた区域として作り(`stages:`と同じ仕組みです。MuJoCoは実行中に本体を追加できません)、引かれた区域の開始姿勢から始めます。区域0は候補を書いた部屋自身で、候補は7個までです(区域ごとにモデルとbuild時間が大きくなります)。
- 休む区域: 引かれなかった区域の部品はその場に残りますが、チャンネルは0で`update`・`substep`も回らず、計画と観測から外れます。そのためどの部屋が引かれても観測と保存の大きさは同じで、観測項目`part_used`が今どの部屋かを示すマスクになります。保存には引かれた区域の番号も入ります。
- 評価専用の部屋: `holdout:`に書いた候補は学習モデルの区域としてはありますが、学習の引きから外れ`wide`でのみ引かれます。評価でモデルを作り直さないので、方策の入力の大きさは変わりません。
- 名前と拒否: 区域ごとに部品名が違う必要があります(チャンネルはモデル全体で共有なので、重なれば拒否します)。ほかに拒否するもの: `stages:`との併用、地図(`map:`)の部屋が部屋を引くこと、地図の部屋を候補にすること(区域は自分の地図を作りません)、候補がさらに部屋を引くこと、開始位置を`region`・`candidates`で引くこと(部屋ごとに座標が違うため`range`のみです)。
- `mpg check`の`resample`段階は、100種がどの部屋を何回引いたかを記録し(`rooms`)、評価専用でないのに一度も引かれなかった部屋があれば警告します。
- サンプルの部屋`examples/rooms/room_roulette.yaml`(task `examples/task_room_roulette.yaml`): 三つの部屋のどれかで目を覚まし、ドアを開く踏み板の位置も壁の隙間も部屋ごとに違うので通る道も変わります。三つめの`roulette_c`は評価専用で学習には出ません。`mpg check`の20種で20/20(平均13.8秒)。
- サンプルの部屋`examples/rooms/mixed_stock.yaml`(task `examples/task_mixed_stock.yaml`): ドアを開く踏み板が「一度踏むと入る」ものと「踏むたびに切り替わる」もののどちらかに引かれ、箱が0〜2個散らばります。`mpg check`の20種で20/20(平均12.7秒)。
- サンプルの部屋`examples/rooms/shuffle_switches.yaml`(task `examples/task_shuffle_switches.yaml`): 三つの踏み板のどれかがドアにつながり、位置も入れ替わります。手本の解答は計画から引かれた配線を読んで歩くので、`mpg check`の20種で20/20(平均12.9秒)です。方策は手がかり(`part_links`か色)を読む必要があり、taskは`target_pos`をあえて外しています。

## キューブとくちばしでつかむ動作

- `cube`は取っ手の付いた箱です(`size`、`mass`、`friction`、取っ手の面`handles`は`+x`、`-x`、`+y`、`-y`、`+z`から選択、既定は側面の4つ)。圧力板、ソケット、物で押すボタンと区域が数えます。部屋にキューブがあると、キューブで入る入力は解く順序で踏み板として数えます。`rest_on: <キューブ>`を付けると、リセットのたびにそのキューブの上面に載って始まります(`pos`はそのキューブ基準のままなので、そのキューブのランダム範囲に付いていきます。自分の`random`は0でなければなりません。下のキューブは別のキューブに載ったものであってはならず、中心がその上面の上になければなりません)。載ったキューブの接触優先度は掛け所の物と同じ(2)なので、ロープのある部屋の掛け所のキューブの上でも、二つのうち大きい摩擦で支えます。
- くちばしでつかむ動作は、実物のアヒルには移せないシミュレーション上の単純化です。シミュレーションのモデルにはくちばしの関節がないので、くちばしの先(`mouth_tip`)が取っ手から`grab_radius`(既定4 cm)以内にあり、つかむ命令が0.5を超えると、頭とキューブの間の溶接拘束を入れます。頭とキューブはぶつかりません。0.5以下にすると放します。質量が体の`max_lift_mass`(既定0.05 kg)より大きいとつかめず、`beak.too_heavy`が1になります。保持に`max_hold_force`より大きな力が要ると落とし、`<キューブ>.dropped`がパルスで出ます。もう一度つかむには命令を一度下げてから上げます。
- くちばしの先は床から0.135–0.21 mの高さなので、床のキューブには届きません。高さ0.17–0.19 mの台の手前の縁に、取っ手を体の方へ向けて置くと、歩いて近づいてつかめます。文字地図では高い床のマス(`legend`の`{type: floor, height: 0.18}`)が台になります。
- チャンネル: `beak.holding`、`beak.held_id`(つかんだ物のマーカー番号、なければ-1)、`beak.too_heavy`、つかめる物ごとに`<物>.held`、`<物>.dropped`。つかまれた物は床のボタン、圧力板、区域、ソケットが数えません。保存データはつかんだ状態まで戻します。ワープは、くわえている物も頭に対する姿勢を保ったまま一緒に運びます。
- 観測項目`beak`: つかんでいるか、つかんだ物の種類(キューブ1、なし0、ほかの物は次の節)、くちばしの先から一番近い取っ手までの相対位置(体の向き基準のx、y、z)。5個。
- 壁のボタン: `button`に`mount: wall`を付けると、壁の面(`pos`)の`height`の高さに`facing`の向きを向いた板(`size`: [幅, 高さ])になります。くちばしの先が板の上にあり、板の前6 cm以内なら押されます(壁に寄って頭を下げると胸が先に当たり、くちばしの先は板から4–5 cm離れるためです)。板の後ろは板の厚さ + 1 cmまでしか数えないので、薄い壁の向こう側のアヒルは押せません。`trigger`は使いません。
- 上位の行動: `task.yaml`の`actions: [move]`(既定)に`head`(頭を下げる1個: -1でそのまま、1で一番低く)と`grab`(1個、0.5を超えるとつかむ)をこの順で足せます。行動の大きさは3に足した数を加えたものです。方策にできないことはスクリプト解答もしません。キューブを運ぶ部屋や低い壁のボタンを押す部屋は、taskに`grab`・`head`がないと`mpg check`の`actions`段階で失敗します。例: `mpg check examples/rooms/cube_plate.yaml --task examples/task_cube_plate.yaml`。
- 解答の`demo:`: `grab <物>`(取っ手の前まで歩き、頭の高さを合わせてつかむ)、`place <物> <部品>`(部品の中心の上へ運んで止まってから放し、離れる)。壁のボタンは`press <ボタン>`か解く順序で、頭を下げて押します。
- 例 [`examples/rooms/cube_plate.yaml`](../examples/rooms/cube_plate.yaml): 台の上のキューブをつかんで圧力板に載せ、ドアを開けます。

## くちばしで扱う物と受ける部品

`cube`のほかにも、取っ手のある物はすべて同じ方法でつかみます(つかむ半径、持てる質量、落とす力、`.held`・`.dropped`チャンネルが同じです)。プリセットは`beak`分類にあります。

| プリセット | 種類 | 既定値 | 用途 |
|---|---|---|---|
| `beak/cube_weight` | `cube` | 4 cm、40 g | はかり・圧力板に載せる重り。体の`max_lift_mass`(0.05 kg)より少し軽い |
| `beak/laundry` | `laundry` | 12 × 10 cm、厚さ6 mm、20 g、4辺の上に縁(`hem`) | 軽い洗濯物。板は硬く、しわは見た目だけです。上の縁をつかみます |
| `beak/key` | `key` | 20 g、頭4 cm、軸5 cm、`-x`端に輪 | 頭にマーカーが付きます。`accept: [<マーカー番号>]`を持つ受ける部品だけが受け取ります |
| `beak/handle_ball` | `handle_ball` | 半径3 cm、30 g、`-x`側に輪 | 放すと転がります。ボールの部品`ball`とは別です |
| `beak/egg` | `egg` | 25 g、半径2.2 cm、高さ6 cm、横に取っ手4つ、`break_height` 0.05 m、`on_break: fail` | 割れると`<卵>.broken`が1になります。くちばしの先は床から13.5 cm上なので、床やかごに放すと割れます。割らずに渡すにはフックに掛けるか高い台に置きます |
| `beak/stick` | `stick` | 長さ20 cm、太さ1.6 cm、20 g、`-x`端に取っ手 | くわえていると、遠い端が壁のボタンを押します |
| `beak/hook` | `receptacle` `shape: hook` | 8 × 8 cmの柱、高さ0.19 mに長さ6 cmのかけ棒、`tolerance` 0.04 m | かけ棒の先から4 cm以内で放した物が掛かります |
| `beak/basket` | `receptacle` `shape: box` | 30 × 30 cm、壁の高さ10 cm、`require: count`、`count: 1` | `<かご>.count`と`<かご>.mass`(kg)で中身を数えます |
| `beak/scale` | `pressure` `trigger: object` | 20 × 20 cm、`min_mass` 5 g | 数値チャンネル`<はかり>.mass`(kg、1 g刻み)。5 gから`<はかり>`が1 |
| `beak/wall_button_beak_low` | `button` `mount: wall` | 板12 × 6 cm、中心の高さ0.15 m、`oneshot` | 頭を下げないと(`head`行動)届きません |
| `beak/wall_button_beak_mid` | `button` `mount: wall` | 板12 × 6 cm、中心の高さ0.2 m、`oneshot` | 立ったままくちばしの先(0.21 m)が届きます |

- 卵: 接触が始まるときの法線方向の相対速度が、`break_height`から落ちたときの速さ(√(2·9.81·`break_height`)、既定0.99 m/s)以上なら割れます。既定の体で測った値(2026-11-12): くちばしから床へ放すと1.42 m/s(頭を一番低く)–1.86 m/s(頭を上げたまま)、台から取って床の板に置くと1.68–1.87 m/s、つかんで運ぶ間の衝突は0.24 m/s以下(台に押し付けると0.49 m/s)、着地後に触れるのは0.35 m/s以下です。そのため5 cmにすると放したときだけ割れます。部品の既定の`on_break`は`none`(チャンネルだけ)、プリセットは`fail`(割れるとエピソード失敗)です。割れた卵は色が変わり、保存データとリセットで戻ります。
- 鍵とソケット: 受ける部品の`accept`には名前と種類のほかにマーカー番号(整数)も書けます。ソケットが同じ番号のマーカーを付けてもよく、このときだけマーカー番号の重複が許されます(ほかの重複は今まで通り拒否)。向きはソケットの`angle_tolerance`で見ます。
- かけ棒: くわえていない物の取っ手がかけ棒の先から`tolerance`以内に来ると、物はかけ棒に固定され、入ったと数えます。もう一度くわえると外れます。かけ棒は見えるだけでぶつからない論理的なかけ棒です(ぶつかるのは柱だけで、柱と掛けられる物の間の接触は切ります)。`facing`がかけ棒の向きです。
- かご: 壁が10 cmより低いと、体が引っかかって転ぶか壁を乗り越えます(5 cmの壁で4回中3回転倒)。10 cmの壁越しには、頭を上げたくちばしの先が壁面から5.8–6.8 cm先まで届きます。
- 棒: くわえている棒の遠い端も、壁のボタンではくちばしの先と同じ窓(板の前6 cm、板の後ろは板の厚さ + 1 cm、板の幅・高さの内側)で数えます。測った値: スクリプトでゆっくり近づくと10回すべて、棒の端が板の面の前2.9–5.9 cm、高さの差2.7 cm以下で押し、押す前の溶接の力は0.89 N以下でした。壁にそのまま歩いて突っ込むと、6回中4回は力が`max_hold_force`(3 N)を超えて棒を落とします。頭を下げると棒の端は大きく下がります(頭1単位で約0.43 rad)。
- 観測`beak`の物の種類: `cube` 1、`laundry` 2、`key` 3、`handle_ball` 4、`egg` 5、`stick` 6、なし0。
- 解答の`demo:`に`drop <物> <部品>`が加わります。`place`と同じく運びますが、頭を上げたまま放します(卵を割る解答)。`place <物> <かけ棒>`は先頭の取っ手をかけ棒の先に合わせて掛けます。棒をくわえて`press <ボタン>`をすると、棒の端を板の高さに合わせて押します。
- 既知の限界: 割れた卵も受ける部品が数えます。かご・はかりに置くスクリプト解答は、部屋とシードによって10回中8–10回成功します。

## くちばしで動かす装置

装置はその場に立っていて、体は`facing`(度)の側から操作します。すべて解く順序のスイッチで、目標領域は体が立って操作する位置です。取っ手で操作する装置は、玉関節についた小さな取っ手の体をくちばしの溶接でつかみます(つかむ半径、離れる力、`.held`・`.dropped`チャンネルは物と同じです)。

| プリセット | 種類 | 既定値 | 用途 |
|---|---|---|---|
| `beak/lever` | `lever` `mode: push` | 3段(-1, 0, 1)、最大35°、-1から始まる、板の高さ7–12 cm | 体が胸で板を押し倒します。`<レバー>.angle`が段の値を出します |
| `beak/pull_cord` | `pull_cord` | 0.45 mから垂らしたひも、取っ手の高さ0.19 m、6 cm引くとオン、`latch` | 取っ手をくわえて向きを変え、歩いて離れるとひもが引き出されます |
| `beak/dial` | `dial` | 羽根4枚(段0–3)、羽根の高さ7–12 cm、半径0.15 m、0から始まる、`target: [1, 1]` | 軸の横0.10 mの線を歩いて通り過ぎると一段ずつ回ります |
| `beak/drawer` | `drawer` | 引き出しの底0.17 m、0.15 m出る、帯0.1 m、取っ手の高さ0.19 m | 帯の取っ手をくわえてその場で時計回りに回ると開き、開いたまま止まります |

- レバー:`detents`が段の数です(既定3、0は連続、1は拒否)。関節ばねが腕を一番近い段へ引き(`detent` N·m)、チャンネルはその段の値だけを出します。`mode: push`は床のレバーで、体が`facing`側から前に歩いて板を-1から1の方へ押します。足は板の下(7 cm)を通ります。`mode: grab`は体の方を向いて立つ腕の上の取っ手をくわえ、横歩きで回すレバーです。測った値のため既定の`max_angle`は10°で、スクリプトの解答はこのレバーを回しません(下記)。
- 引きひも:ひもは1Dのflexcompで、重力補償により重さがありません。ひもの上端は腕の中のばね付きスライダーにかかっていて、引くとひもが出てきて、`distance`だけ出ると`<ひも>`がオンになります。`latch`ならリセットまでオンのままです。ひものばね`stiffness`は既定で2 N/m。
- 引き方:取っ手をくわえたままその場で時計回りに回って装置に背を向け、前に歩きます。既定の体は後ろに歩けず、その場で反時計回りにはほとんど回れません。

```text
  上から見た図 (facing側が下)

   [柱]─腕─o ひも          1. 取っ手の前に立ってくわえる
            │
            ●  取っ手      2. くわえたまま時計回りに回る
            ▲
           アヒル          3. 前に歩くとひもが引き出される → オン
```

- 測った値(2026-11-12、既定の体、`max_hold_force` 3 N):つかむレバーの取っ手をくわえて横歩きすると、体の右へは9.5–15.7°回ったところで溶接の力が3 Nを超えて離れ、左へは体が動きませんでした(12秒で0.2°以下)。同じ場所でつかまずに横歩きすると4秒で0.19–0.25 m進みます。押すレバーは5回とも転ばずに3.2–4.3秒で1まで倒れました。引きひもは取っ手をくわえて回るのに4.5–5秒、解答ではオンになるまで全部で9–11秒かかりました(ばね4 N/mでは3.5–3.7 cmで歩みが止まり、オンになりません)。
- ダイヤル:軸の立った床のダイヤルで、羽根は取っ手ではありません。体が`facing`側で軸から0.10 m離れた線を、軸を左に見て前に歩いて通り過ぎると、胸が羽根を一枚押して一段(羽根4枚なら90°)回ります。向きは一方向(上から見て反時計回り)だけです。次の段は時計回りに歩いて回って戻り(後ろには歩かない)、同じ側をもう一度通ります。そのため`facing`側に1 mほど空けておきます。`<ダイヤル>.angle`が段の番号(0–3)で、砲台の狙いにも使えます(段ごとに狙う)。`<ダイヤル>`は段が`target`の範囲にあるとき1です。
- 引き出し:台の高さ(0.17 m)の引き出しがキャビネットに入っていて、前板の重さのない帯(1D flexcomp)の先に取っ手があります。取っ手をくわえてその場で時計回りに回ると引き出しが引き出され、ほぼ全部(97%)出ると開いたまま止まり、`<引き出し>`が1になります。それからは帯の取っ手はつかめません(くわえていれば離します)。閉じた引き出しの中(前から0.09 m以内)に置いた物は底に載り、引き出しといっしょに出てきて、くちばしでつかめます。それより奥だと`mpg check`の`parts`段階で失敗します。`pos`はキャビネットの前面、`facing`が開く側です。
- ダイヤル・引き出しの測った値(2026-11-12):軸の横0.10 mを通るとvx 0.25・0.4どちらも10回中10回ちょうど90°、0.12 mでは10回と9回、0.14 mでは5回で、転倒はありませんでした。段3に合わせるのは10/10(一周約11秒、全部で約33秒)。帯0.1 mで取っ手の位置と向きをばらつかせても(±2.5 cm、±0.15 rad)、10回とも4.8–14.1秒で開いて止まり、溶接の力は0.38 N以下、離れることはありませんでした。帯6 cmでは同じ条件で6/10でした。解答(`pull`のあと`grab`)は10回とも開けて中のキューブをつかみました(前から0.08 mのキューブ。0.12 m奥のものは届きません)。
- 観測`beak`の物の種類:`lever` 7、`pull_cord` 8、`drawer` 9。
- 解答の`demo:`:`turn <レバー> <値>`(押すレバーだけ、値は段のひとつ。レバーの前まで歩いて押し、止まって回ってから離れる)、`turn <ダイヤル> <段>`(その段になるまで通り過ぎと時計回りの戻りを繰り返す)、`pull <ひもか引き出し>`(オンになるか開いて止まれば離す。くわえて6秒間1 cmも引けなければ離して来直す)、`look <部品>`(`<部品>.seen`を読む部品があるとき、その部品を視野の真ん中に入れて立つ)。格子の解答も、解く順序にレバーが来れば1まで押し、ダイヤルは最初の目標の段まで回し、ひもは引き、引き出しは開けます。引きひもか引き出しがあればtaskの`actions`に`grab`が必要です。
- 砲台とレバー:砲台が`bind`でレバーの`.angle`を読むと、`mpg check`の放物線の点検は連続した範囲ではなくレバーの段ごとに狙います。信号で狙い、信号がオンになると撃つ砲台がある部屋では、的の板(`input/target`)が解く順序のスイッチになり、その目標領域(観測`target_pos`も)は砲台を撃たせる入力部品の位置です。`.angle`を`bind`だけが読むレバー・ダイヤルは設定のつまみでスイッチではないので、1まで押しても`new_on`の報酬はなく、格子の解答も押しません(狙いは`demo:`の`turn`)。
- 例[`examples/rooms/turret.yaml`](../examples/rooms/turret.yaml):レバーを一段押して砲台を的に向け、床の板を踏んで撃つと扉が開きます。
- 既知の限界:つかむレバーはスクリプトの解答が回しません(`turn`が拒否します)。押すレバーは一方向(-1 → 1)に押すのが基本で、戻す(1 → -1)ときは反対側から押します。ダイヤルは一方向にしか回らないので段は0–3を巡り、一段進むたびに約11秒かかります。ダイヤルの戻りの輪は静的な点検が見ません(`facing`側に1 m)。引き出しを開けるのに4.8–14秒かかり、開いた引き出しはリセットまで閉まりません。

## ディスペンサー

`dispenser`は、信号がオンになるたびに物を一つ出すキャビネットです。`pos`がキャビネットの前面、`facing`(度)が体の立つ側、天面の高さ`height`(既定0.17 m)はくちばしが届く台の高さです。

| プリセット | 種類 | 既定値 | 用途 |
|---|---|---|---|
| `beak/dispenser` | `dispenser` `button: floor` | `beak/cube_weight` 5個、`max_active` 1、`cooldown` 1 s、前0.35 mに20 × 20 cmの床プレート | プレートを踏むと天面の前の縁におもりが一つ出ます |
| `beak/dispenser_wall` | `dispenser` `button: wall_beak` | 同じ物と在庫、前面0.14 mの高さに10 × 5 cmのプレート | 頭を下げて(`head`行動)くちばしでプレートを押します |

- 既定の物が`beak/cube_weight`である理由: 四つの側面に取っ手があってどちらから近づいてもつかめ、40 gで体の`max_lift_mass`(0.05 kg)以内、天面の高さは「くちばしが届くのは0.17–0.19 mの台の上の物だけ」という測定値に合わせました。
- トリガー(`button`): `floor`は`button_at`([前, 左] m、既定[0.35, 0])の床プレート、`wall_beak`は前面`button_height`の高さの壁プレート(R4の窓、プレートの前6 cm)、`none`は`in`チャンネルです。プレートがあっても`in`チャンネルがオンになれば数えます。
- 出す物(`item`): つかめる物のプリセット(R28)かNPCのプリセット(R29)の名前、または`{preset: <名前>, <値>: ...}`のように上書きする値と一緒に。ほかの種類は部屋を読むときに拒否します。
- `stock`(最大20): 前もって作る複製の数。`max_active`: 同時に外に出ていられる数。`cooldown`: 次の一つまでの待ち時間。`refill`(チャンネル): オンになるたびに保管中の複製をすべて在庫に戻します。出口`exit`([前, 左] m、既定は物なら天面の前の縁から2 cm内側、ロボットなら前0.15 mの床)と初速`exit_vel`([前, 左, 上] m/s、転がして出す)。
- チャンネル: `<ディスペンサー>.stock`(残り数)、`<ディスペンサー>.empty`(なくなると1)。複製は部品`<ディスペンサー>/<番号>`で、`.held`・`.dropped`チャンネルもその名前で出ます。同じディスペンサーの複製はマーカー番号を一つ共有します。
- 保管: MuJoCoは実行中に体を足せないので、複製は前もって作ります。保管中の物は床の5 m下で衝突を切り、重力を補正して止まっています。ロボットは部屋の外100 mの床の高さで駆動を切ります。保管中の複製は観測(`part_pos`、`part_state`、`npcs`、`beak`)、くちばしでつかむ動作、視界(`.seen`)、センサー、解答に現れません。スナップショットとリセットが在庫と位置を戻します(リセットは在庫を満たします)。
- 消費(`consume`): 受ける部品(`receptacle`、例: `beak/basket`)に`consume: true`(既定false)を付けると、受け入れた物は消え、受けた数(`.count`、`.mass`)には残ります。消えたのが複製なら外に出ている数から外れ、ディスペンサーが`recycle: true`なら在庫に戻ります(そうでなければ`refill`まで保管)。穴や崖から落ちた複製も同じように戻ります。
- 解答の`demo:`: `take <ディスペンサー>`(プレートを踏むか押して一つ受け取り、出た物が止まるまで立つ)。そのあと`grab <ディスペンサー>`、`place <ディスペンサー> <部品>`、`drop <ディスペンサー> <部品>`は最後に出た複製を扱います。格子の解答は、解の順序の受ける部品が受け入れる物が部屋に残っていなければ、ディスペンサーから一つ受け取って運びます。壁プレートのディスペンサーから受け取る部屋はtaskの`actions`に`head`が、物を運ぶ部屋は`grab`が必要です。
- 測定値(2026-11-12、シード10個、ディスペンサー`[-0.2, 0.33]` `facing: -90`、かご`[0.25, -0.1]` `consume: true`): `demo: [take d, grab d, place d bk]`が床プレート9/10(9.9–13.3 s)、壁プレート10/10(12.7–25.8 s)。かごが扉を開ける部屋では、格子の解答がかごを床プレート10/10、壁プレート9/10でオンにし、目標まで40 s以内に着くのは床プレート40/40、壁プレート35/40です(標準の0.56 mの扉の隙間、シード40個)。`take`を続けると、プレートから降りてディスペンサーの準備ができたら(`cooldown`)もう一度押します。
- 既知の限界: かごに入れる成功率はかごの位置によって10回中4–10回です(縁に引っかかる、かごの壁にもたれて転ぶ、かごと部屋の壁の間の隅に閉じこもる)。かごに放したあとは物が止まるまで(消費されれば1.5秒)立ってから、かごの中心から0.28 m(かごの幅の半分 + 体の半径 + 2 cm)まで離れます。置きに行く途中でかごの壁がすぐ前にあり、物がかごの内側の上にあれば、立ったまま放します。格子の解答の計画はかごの壁を障害物と見ます。壁の実際の隙間が体の半径 × 2 + 0.1 m(Microduckは0.32 m)より狭いと計画の格子で塞がり、解答が扉の前で回り続けることがあります。標準の隙間(壁の端の間0.56 m、実際の隙間0.50 m)を使ってください。解答は`button: none`のディスペンサーの入力条件や`max_active`がふさぐ場合を見ません(`mpg check`の動的段階が見つけます)。ロボットを出すディスペンサーはスクリプト解答が使いません。

## アドオンステーション

`addon_station`(プリセット`device/addon_roller`)は、体にアドオン(今は車輪`roller`の一つ)を付け外しする床パッドです。MuJoCoは実行中に体を足せないので、ステーションが一つでもある部屋では、足モデルの両足首の下に公式車輪モデルの車輪4個をあらかじめ付けた合成モデルを作ります(最初は外した状態: 車輪の衝突オフ、非表示)。ステーションのない部屋は今までとまったく同じに作られます。

- 切り替えるとき: 胴体がパッドの中にあり、水平速度が`max_speed`(既定0.1 m/s)より遅く、信号が来たとき。`in`チャンネルがあればそれがオンになったとき(オンのままなら、あとからパッドに来て止まっても切り替える。オンになるたびに一回)、なければパッドに乗ったとき(乗るたびに一回)です。`mode`は`attach`(付ける)、`detach`(外す)、`toggle`(切り替え)。`enable`がオフなら切り替えず、切り替えたあと`cooldown`秒は再び切り替えません。
- 切り替えでやること(体アダプターの`set_addon`): 車輪か足のメッシュ最低点で胴体の高さを合わせ(付けるとき+23.6 mm、外すとき−15〜−23 mm)、体の速度を0にしてから、衝突リスト・車輪の表示・下層ポリシー(`velstand` ↔ `roller.onnx`、関節は名前で対応)とポリシー履歴を切り替えます。付けた状態の衝突リストは公式車輪モデルのもの(車輪を含む13個)です。
- 車輪状態の行動: 前の値は押す強さ(−0.6未満は押さず、1秒ほどで止まる。それ以上は0.25〜0.6)、回転の値は目標方向の回る速さ(±1 rad/s。アダプターが目標方向との差を±0.5で切ってポリシーに入れる)です。横の値と`head`は車輪状態では使いません。最大で押すと約0.32 m/s(歩きは最大約0.22 m/s)、回転1で転がりながら1.00 rad/s、立ったまま0.78 rad/s回ります。
- 信号と観測: `<ステーション>.attached`(車輪を付けている間1)、`body.addon`(0なし、1 roller。部屋の最初のステーションが書く)、観測項目`addon`(現在のモードのワンホット、2個)。
- リセットはいつも足の状態(`velstand`)から始まります。チェックポイントの保存はモードを含み、車輪状態の保存に戻ると車輪状態になります。ワープは車輪を付けたまま運びます。
- `crouch`行動: taskの`actions`に`crouch`を入れると(順序は`head`、`grab`、`crouch`)行動が一つ増え、0.5を超えると`roller_crouch.onnx`を3.5秒動かします。車輪状態でないか、速度が`env.crouch_min_speed`(既定0.2 m/s)未満なら無視します。かがんでいる間の転倒判定は傾きだけを見ます。測定値: 胴体の最低0.067 m、かがむ3.5秒の間に0.41〜0.54 m滑走、かがみ28回で転倒0。
- 解答の`demo:`: `addon <ステーション>`(パッドの中央へ歩いて行き、モードが変わるまで立つ)。格子の解答はステーションを使いません。
- 測定値(2026-11-13、シード20個): 立ったまま付けて指令0/0.3/0.4で2秒、止まってから外して指令0で2秒、そのあと3秒歩いて転倒0、最大傾き9.3°/13.8°/14.1°(付けたあと)、10.6°以下(外したあと)。1 cmの段差タイルの上でも転びません(テスト、シード10個)。
- 速度区域: 区域センサー(`zone`)に`min_speed` [m/s]を与えると、対象がその速さ以上で動いている間だけ数えます。速さはステップ間の動きを約0.5秒でならした値(速度ベクトルのローパス)なので、歩きの左右の揺れは消えます。測定値(2026-11-13、シード3個): 全力で歩くと0.20–0.25 m/s、車輪で全力で押すと0.32–0.53 m/s。車輪プリセットは0.28を使います。`rearm: leave`か`direction`があると、速さはオンになる瞬間だけ見ます。なし(既定)なら以前と同じです。
- ブレーキ帯`brake_strip`(プリセット`trap/brake_strip`): 胴が帯の上にあり帯が働いている間(罠の規則: `in`、`enable`、`enabled`)、車輪関節4つの`frictionloss`と`damping`を帯の値に上げ、体が離れると元の値(0.0015、0)に戻します。モデルの値なので、スナップショットとリセットも戻します。帯が複数あれば、体の下の帯の大きいほうの値を使います。足の状態では車輪が床に触れないので何も起きません。ステーションのない部屋に置くと点検が警告します。測定値(0.29–0.48 m/sで転がり込んだとき、シード5個): `frictionloss` 0.01なら押し0で帯の端から0.08–0.12 m(0.4–0.6秒)、押し続けても0.12–0.13 m以内で止まり、転倒0。0.004だと押せば転がり続け、0.03や`damping` 0.002以上は0.44 m/sから転びます(止まり方が急すぎる)。0.01の帯の上で止まったアヒルは車輪では出られないので、外すステーションの下か道の終わりに敷きます。
- 低い棒`low_bar`(プリセット`device/low_bar`): 道を横切る固定の箱(奥行き4 cm、厚さ3 cm)です。`axis`の向きに`length`だけ置かれ、下面の高さが`bottom`(既定0.228 m、範囲0.21–0.246 m)です。体とぶつかり、状態がないのでスナップショットに入れるものはありません。範囲は測った値です: かがむと胴は下がりますが、頭(`jaw_soft`)のてっぺんは0.256–0.268 mから0.197–0.200 mへ7 cmほどしか下がりません(かがんでから約0.7–2.3秒)。そのため下面は、かがんだ頭より1 cm上、立った車輪の頭より1 cm下にします。歩いても車輪で立ったままでもぶつかって止まります。解く順序は棒を壁と見ますが、部屋に車輪を付けるステーション(`attach`か`toggle`)があれば、すべってくぐれると見ます。そのようなステーションがなければ点検が警告します。道を全部横切るように置きます(廊下の幅より数cm短く。壁と重なると点検`overlap`で失敗)。
- 解答の`glide <棒>`: 車輪の状態で、胴が棒の中心線から1 mより近ければ1.2 m手前まで戻り、棒に向いてから棒の真ん中を通る線に沿って最大で押し、胴が中心線の0.30 m手前に来たら`crouch`を送ります(10 Hzなので実際は0.26–0.30 m)。中心線を0.3 m過ぎたら終わります。taskの`actions`に`crouch`が必要です(なければ点検`actions`段階で失敗)。測定値(0.228 mの棒、1.5 mの廊下、シード20個、かがみ始めの距離0.2/0.25/0.3/0.35/0.4/0.5 m): 進入0.32–0.48 m/sで6/14/20/20/20/7回、0.35–0.41 m/sで19/20/20/20/0/0回、触れずにくぐります。かがまなければ20/20止まります。最大で押すと3–4秒の助走で0.38–0.45 m/sになり、進入が0.29–0.35 m/sだと9/20以下なので、助走は1 mより長く取ります。`crouch_min_speed`(0.2 m/s)はかがみ始められるしきい値にすぎず、棒をくぐるには約0.35 m/s以上が必要です。
- 段の警告(`mpg check`の`parts`段、失敗ではない): 部屋の最初のステーションが、付ける・切り替えるパッドごとに床を塗りつぶしてみます(スイッチは全部オン、ほかの外す・切り替えるパッドはふさぐ)。高さの違う床(文字マップの段のマス、高さのある床タイル、3 mm超)に届けば、車輪の状態で段へ行ける道なので警告します。車輪のポリシーは段を上れません。外すパッドを道を横切って敷いてください。
- 車輪の組み立てプリセット`puzzles/roller/`(どれも部屋一つ全体、`demo:`付き、`mpg check`シード20個)。時間は成功の平均です。`glide_under`と`roll_delivery`は行動がさらに要るので、taskと一緒に点検します(`mpg check <プリセット> --task examples/task_glide_under.yaml`)。

## 牽引ロープ

`rope`(分類`device`)は二つの結び目をつなぐロープです。結び目どうしが`length`(既定0.4 m)以内ならたるんで力がなく、超えると引きます(MuJoCoの空間テンドン、範囲0..`length`)。結び目は20 g以上の小さな円板(`knot_mass`)で、床にだけ触れます(体と物は通り抜けます)。結び目の上`handle_height`(既定0.16 m)の輪をくちばしでつかみます。結び目はボタン・圧力板・区域のどの`trigger`にも数えません。

- 掛け所(hitch): ロープの端を結べる所。体(`body`、胴体の下の床から0.04 m)、`hitch: true`の物(その中心)、NPCロボット、固定の柱`anchor`(`hitch_height`、既定0.04 m。描くだけで体は通り抜けます)、ロープ扉`rope_door`(板の上辺の中央)。ロープの`a`、`b`が端の掛け所の名前、`tied`(既定は両方)がリセット時に結ばれている端です。結ばれていない端の結び目は`rest`([[xa, ya], [xb, yb]]、既定は`pos`からxに∓0.4 × `length`)に置かれます。部屋の掛け所は`max_hitches`(既定16、体を含む)までです。ロープのある部屋では`hitch: true`の物の摩擦が床より優先されます(物の`friction`が引く荷の重さを決めます)。
- 結ぶ・ほどく三つの道:
  - 連結パッド`hitch_station`: 胴体がパッドの上にあり`max_speed`(既定0.1 m/s)より遅いとき、信号(`in`チャンネルがオンになる瞬間、なければパッドに乗る瞬間)が来ると、体の掛け所からロープの`hitch_radius`(既定0.3 m)以内で一番近い掛け所と体をつなぎます(`attach`。その掛け所にすでに結ばれた端はそのまま、もう一方の端が体に来ます。すでに体に結ばれ、もう一方の端がほどけているロープはその端を結びます)。`detach`は体側の端をほどき、`toggle`は合う方をします(ロープがすでに体と何かをつないでいなければ結ぶ)。`handoff`は体に結ばれたロープの端を、同じステップのうちにパッドの`to:`の掛け所(ふつうは固定の柱)へ移します。結び目をその掛け所へ移して拘束を一度に切り替えるので、荷を持つロープがたるみません。張力のかかった端はくちばしではなくこの方式で移します(荷がくちばしの耐える力より大きい)。`cooldown`(既定1 s)と`enable`はアドオンステーションと同じです。`rope`でロープを選びます(部屋にロープが一本なら省略可)。出力`<パッド>.towing`。
  - チャンネル: ロープの`attach_a`、`detach_a`、`attach_b`、`detach_b`がオンになる瞬間、その端を`a`/`b`(なければ結び目から`hitch_radius`以内で一番近い掛け所)に結ぶかほどきます。
  - くちばし: 結び目をくわえて掛け所の`clip_radius`(既定0.04 m)以内で放すと結ばれ、結ばれた結び目を`untie_time`(既定0.5 s)くわえ続けるとほどけます。そうしてほどいた結び目は、その場で放しても結ばれ直しません(くわえ直して放すと結ばれます)。
  - 結ぶとき、もう一方の端までが`length`より遠ければ(ロープに沿って、滑車を通って)結ばず、`<ロープ>.attach_failed`を1ステップ出します(範囲内に掛け所がないときも)。結ばれた結び目は掛け所の位置に移されてから連結拘束(`connect`)で付きます。
- 長さ: `length`は実行中の値なので、`bind`でレバーなどのチャンネルにつなげます(巻き上げ機)。目標が一度に変わっても、実際の長さは`reel_speed`(既定0.05 m/s)で追います。スナップショットは現在値と目標値を両方保存します。
- 滑車: `via: [[x, y, z], ...]`は、ロープが端aからbへ順に通るワールドの点(天井の滑車。車輪として描き、衝突なし)です。`length`は経路全体にかかり、結ぶ・パッド・静的点検も経路に沿って測ります。
- 切れる: 張力が`max_tension`(既定0.9 N)を`snap_time`(既定0.2 s)より長く超えると両端がほどけ、`<ロープ>.snapped`が1になります(リセットまで)。`on_snap: fail`なら切れた時点で失敗です。
- チャンネル: `<ロープ>.attached_a`、`.attached_b`(結ばれている間1)、`.tension`(`max_tension`に対する0..1、1ステップの平均)、`.snapped`、`.attach_failed`、`body.towing`(体に結ばれたロープがあれば1。部屋の最初のロープが書きます)。観測項目`tow`: 体に結ばれているか、張力(`max_tension`に対する0..1)、もう一方の端(結ばれていればその掛け所、なければ結び目)の体基準の位置(x、y)。4個。観測`beak`の物の種類では結び目は10です。
- NPCを結ぶと、ロープがかかっている間そのロボットの駆動ゲインが0になり、リード(`leash`)の制限が外れて引きずられます。滑り続けないよう、平面移動の関節に減衰(1.0 N·s/m)をかけます(体が止まると1秒以内に止まる、歩くときの張力の平均0.20 N)。ほどけると駆動が戻り、リードの箱の外にいれば中へ歩いて戻ってから制限をかけ直します。リセット・スナップショットの復元・結び目の変化のたびにロープの状態から計算し直します(保存しません)。もう一方の端がほどけていても、ロープの端が一つでもかかっていれば結ばれているとみなします。計画: ロープがNPCに結ばれうるとき(ロープの`a`/`b`がそのNPCか、パッドで結ぶ空きの端があるとき)、NPCがオンにするセンサー(`trigger: npc`か`any`、`objects`なし)はロボットのリードの外にあってもスイッチとして数えます。体がロボットを引いていくからです。
- ロープ扉`rope_door`(役割gate): 壁のすき間の板が、駆動のない垂直のスライド関節に付いていて重力で閉まります(`width`、`axis`、`thickness`、`height`は引き戸と同じ。体・物と衝突し、壁とは衝突しません)。掛け所が板の上辺の中央なので、真上の滑車を通るロープのもう一方の端を遠くへ引くと扉が上がります。`mass`は既定0.05 kg、最大0.15 kg(1.47 N)。`clearance`(既定0.34 m。歩くMicroduckのてっぺんが0.30 m、測定値)だけ上がると開いたとみなします: チャンネル`<扉>.lift`(`clearance`に対する上がり具合0..1、状態値と同じ)、`<扉>.open`。静的な順序は、結ばれうるロープの滑車(`via`の点)のひとつが板の上にあれば(xyが板の床の範囲内、zが開いたときの掛け所の高さ`height` + 0.003 + `clearance`より上)開けられる扉とみなし、`demo:`の歩きはほかの扉のように0.3ではなく、上がりきったときだけ通ります。そういうロープがなければ`parts`段階が失敗します。ロープが板と20 gの結び目の重さを持つので、そのロープには別に`max_tension`を与えます(`cleat_hold`: 1.5 N)。
- ワープ: 体をワープすると、ロープでつながった一団(物、結び目、NPC、さらにそれにつながったもの)を同じ相対姿勢で一緒に移します。一団の中の固定端(`anchor`、`rope_door`)は先にほどきます。滑車(`via`)を通るロープは一緒に移せないので、一団側の端をほどいてロープは残します。物だけがワープされたとき、スプリングが物を蹴ったとき、ディスペンサーが複製を回収したとき、受ける部品が物を吐き出したときは、その物のロープを先にほどきます。アドオンを替える(`set_addon`)ときは体側の端を先にほどきます。
- 点検(`mpg check`の`parts`段階): `hitch_radius`と`clip_radius`が`length`(最初と最後の滑車の間の経路を引いた値)以下か、リセット時に既定で結ばれた両端がランダム範囲を入れてもロープに沿って`length`以内か(失敗)。引く荷(摩擦 × 重さ)が0.4 Nを超えるとき、また`demo:`の`tow`と`untow`の間の道に引く物より狭い扉や、`length`以内で90°より急な曲がりがあるときは警告します。この道には`drag`の区間と、リセット時に体と物・NPCをつなぐロープならスタートからの道も入ります。`demo:`が穴へ引き入れる箱(`drag <ロープ> <穴>`)は、高さが穴の深さ(`depth`、なければ縁から0.5 m下の受け面まで)と1 cm以内で同じで上面が床とそろい、穴の口が箱の一番大きい横の大きさ(取っ手込み)より両辺とも0–4 cm広くなければなりません(失敗)。静的な解く順序は、`depth`の穴に合う`hitch: true`のキューブがあり、ロープがそれに結べる(`a`/`b`で名指し、または空いた端)とき、その穴を穴として扱いません。
- 解答の`demo:`: `tow <ロープ> <掛け所>`(そのロープを体と掛け所につなぐ連結パッドへ歩いて立つ。パッドをすでに使っていれば降りてまた乗る)、`untow <ロープ>`(ほどく・トグル・`handoff`のパッドへ)、`drag <ロープ> <部品>`: 引かれる掛け所はロープの体と反対側の端です(ロープが鎖のようにつながっていれば、鎖でより遠い端)。体は、掛け所(段階が始まったときの位置)から部品の中心を通る線の上で、部品の中心の先の点へ歩きます。その先の距離はロープの長さか体と掛け所の距離(鎖)の長い方より0.25 m遠く、壁の手前で止めます。掛け所が部品の床の領域に5 cm入るか、途中でほどけたら(その部品の`detach_*`チャンネル)終わります。部品には床の領域が必要です(圧力板、区域、パッド、穴)。`drag`の段階が満たすセンサーは`grab`の行動を求めません。
- 測定値(2026-11-13): 0.2 kgのそり(摩擦0.1)を0.4 mのロープで引いて歩くと、そりは約0.39 m後ろを付いて来て張力は0.1–0.43 N。0.3 kg(摩擦0.5、荷1.47 N)は歩き出すとすぐ切れます。柱に結んだ0.3 kgのそり(摩擦0.5)で`length`の目標を0.4 → 0.1 mに一度に変えると、最大張力は`reel_speed` 0.05/0.1/0.5/2.0 m/sで1.86/2.11/5.06/13.7 Nです(2.0ではそりが柱を通り過ぎます)。体の掛け所はOpen question 9の0.04 m(股関節の軸の中間の下、胴体基準(0.007, 0, −0.0756) m)です。
- 牽引の組み立てプリセット`puzzles/tow/`(どれも`demo:`のある部屋一つ全体、荷は0.4 N未満。taskは`move`だけで、つかむ必要がある`overload`は`examples/task_overload.yaml`(`[move, head, grab]`、120 s)で点検)。引いていった荷は圧力板ではなく物の区域(`input/object_zone`)に置きます。圧力板の4 mm盛り上がった縁が引かれる箱を止めるためです(0.1 m・0.2 kgのキューブ、摩擦0.1は縁でロープが切れた、最大2.8 N。0.15 kgは最大2.0 Nで乗り越えた)。

## Pythonプラグイン

新しい部品は`Part`を継承し、`register_part`で登録します。値を`fields`に`Field`として書けば、範囲の検査と`mpg parts`の表が自動でついてきます。ゲートの関数は`register_logic`で登録し、部屋では`logic: <名前>`で呼びます。

```python
# my_parts.py
from mujoco_puzzle_gym.parts.base import Part
from mujoco_puzzle_gym.registry import register_logic, register_part
from mujoco_puzzle_gym.schema import Field

@register_part("timed_switch")
class TimedSwitch(Part):
    role = "switch"
    stage = "input"
    emits = True
    fields = (Field("seconds", "float", 2.0, unit="s", min=0.1, max=60.0),)
    ...

@register_logic("majority")
def majority(inputs, state, dt):
    return float(sum(v > 0.5 for v in inputs.values()) * 2 > len(inputs))
```

`task.yaml`に`plugins: [my_parts]`と書くと、学習のワーカープロセスまで含めて、このモジュールを最初に読み込みます。プリセットのフォルダーはこのパッケージの中にしかありません。自作の部品の既定値のセットは、部屋のファイルに値として書きます。
