Status: approved 2026-11-11 (user: "응 그리고 몸 갈아끼기 어댑터는 필요해보이고")

## Problem
- 공개된 로봇 학습 환경(CALVIN, Franka Kitchen 등)은 장면이 고정되어 있고, 장치 상태(버튼·문)가 바뀌는 여러 단계 퍼즐을 실제 로봇 몸으로 학습시키는 공개 표준은 아직 찾지 못했다(2026-11-10 대화에서의 조사, 검증 전 판단).
- MuJoCo MCP 서버들은 대부분 "조작하고 보는" 도구다. 에이전트가 만든 환경이 정말 학습 가능한지 확인하는 고리(장면 → 점검 → 짧은 학습 → 진단)는 드물다.
- 사용자는 교재(로보틱스 노트)에서 배운 URDF, 물리엔진, PPO·보상 설계, 평가, 무작위화를 실제 프로젝트로 써 본 적이 없다.

## Desired outcome
- 시뮬레이션 속 마이크로덕이 발판을 밟아 문을 열고 골에 도착하는 영상이 나온다.
- 처음 보는 배치에서의 성공률이 숫자로 나온다.
- 저장소 `Song-Seng-Hun/mujoco-puzzle-gym`에 README, 데모 영상, CI 배지와 함께 올린다. private로 시작하고, 어느 정도 만들어진 뒤 공개한다. 공개 후에는 다른 사람도 받아서 돌려 볼 수 있다.
- 핵심 메시지: 에이전트가 퍼즐 실험장을 세팅하고(장면), 풀 수 있는지 점검하고, 학습시키고, 실패 원인을 알려 준다.
- 첫 마일스톤에서는 사람이 단계를 손으로 진행해도 된다. 에이전트가 스스로 도는 순환(build → check → train → diagnose)은 그다음이다.

## Users and scope
사용자
- 1차: 사용자 본인(포트폴리오, 학습).
- 2차: 마이크로덕이나 Open Duck 계열 오리를 가진 사람, 로봇 학습을 공부하는 사람.

범위 안 (첫 마일스톤)
- 몸 어댑터 경계: 퍼즐 쪽은 몸을 모른다. 어댑터는 이동 명령(앞뒤·옆·회전 속도)을 받아 몸을 움직이고 몸 상태를 돌려준다. 첫 구현은 마이크로덕 하나.
- 몸: 마이크로덕 시뮬레이션 모델 + 공개된 걷기 정책(고정, 다시 학습하지 않음).
- 자산 받기: 저장소에는 우리 코드만 둔다. 명령 하나로 공식 저장소 고정 커밋의 모델·메시와 Hugging Face의 걷기 정책을 받아 해시로 확인하고 라이선스를 안내한다. MuJoCo 자체는 파이썬 의존성으로 설치된다.
- 퍼즐: 발판 1개 → 문 열림 → 골. 밀기 없이 걷기만으로 풀린다.
- 위층 정책: 퍼즐 상태를 보고 "어느 방향으로 얼마나 빨리 걸을지"를 낸다. 관측은 몸 감각 + 특권 상태(발판·문·골의 상대 위치와 상태).
- 학습: 맥 스튜디오 CPU MuJoCo.
- 결과물: 학습된 정책, 성공률, 영상, 재현 방법.

범위 밖 (나중 후보)
- 에이전트 자동 순환 도구와 MCP.
- 시간 제한 문, 밀기 블록, 경사로, 퍼즐 자동 생성기.
- 다른 몸 어댑터 구현(떠 있는 그리퍼, SO-101 등).
- 실물 센서만 쓰는 학생 정책(ToF 8×8, 카메라 마커), sim2real, 실물 오리.
- 윈도우 2060 MJX 학습.
- 걷기 정책 재학습.

## Affected users and systems
- GitHub 저장소 `Song-Seng-Hun/mujoco-puzzle-gym`(private, 나중에 공개). notes 저장소와 분리.
- 맥 스튜디오: 파이썬 환경, MuJoCo 설치.
- 교재(notes)와는 링크만 주고받는다. 교재 내용은 바꾸지 않는다.

## Constraints
- 공식 마이크로덕 자산(모델, 걷기 정책)의 라이선스를 지키고 출처를 밝힌다.
- 학습은 맥 CPU에서 현실적인 시간 안에 끝나야 한다(목표치는 spec에서 정한다).
- 공개할 저장소이므로 키, 토큰, 개인 정보, 내부 데이터(IDMT, BabySlakh, RWC 등)는 넣지 않는다.
- 저장소 생성, push, PR은 사용자 승인 후. 병합과 브랜치 삭제는 사용자가 한다.
- 범위를 작게 유지한다. 첫 프로젝트에서 가장 흔한 실패는 범위가 커서 끝을 못 보는 것이다.

## Known facts (2026-11-11 조사, 출처 확인)
- 걷기 정책: Hugging Face `pollen-robotics/microduck-policies`(Apache-2.0)에 ONNX로 공개되어 있다. manifest상 기본 걷기 정책은 `velstand.onnx`이다. 걷기와 제자리 서기를 한 망으로 하고, 거친 지형+백래시 과제로 학습되었다. 입력 61차원, 출력 관절 목표 14개, 50Hz.
- 명령: 61차원 중 13차원이 명령(이동 3 + 머리 자세 4 + 몸 자세 6)이다. 걷기 과제 설정의 명령 범위는 앞뒤 ±0.4 m/s, 옆 ±0.3 m/s, 회전 ±1.0 rad/s다. velstand도 같은 범위인지는 아직 확인 전이다.
- 맥에서 돌리기: 공식 저장소 `pollen-robotics/microduck_rl`의 `scripts/infer_policy.py`가 일반 CPU MuJoCo + onnxruntime으로 ONNX 정책을 돌린다. 모터 모델 `better-actuator-models`는 순수 파이썬 패키지(파이썬 3.12)다. 학습용 스택(mjlab, MuJoCo Warp)은 CUDA가 필요하지만, 우리는 걷기 정책을 다시 학습하지 않으므로 필요 없다.
- 로봇 모델: MJCF와 메시가 저장소에 있다(`src/mjlab_microduck/robot/microduck/`). 코드는 Apache-2.0이지만 메시는 CC BY-NC-SA 4.0(비상업, 동일 조건)이다.
- 센서: 8×8 ToF 시뮬레이션(`sim/tof.py`)과 카메라(`sim/camera.py`)가 공식 저장소에 이미 있다. 나중의 학생 정책 단계에 쓸 수 있다.
