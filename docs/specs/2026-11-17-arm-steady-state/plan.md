## 단계 0 — 재기 전에 아무것도 고치지 않았다 (그리고 그게 판정을 뒤집었다)

| 무엇 | 결과 | 뜻 |
|---|---|---|
| 무부하 정속·정지·구동 | 오차 0.0001 m, 추종 0.969–0.999 | 평면은 이미 건전 |
| 부하(30 g) 구동, 범위 **밖** 목표 | 52 mm | **결함 아님** — `_clamp`가 선언 도달에서 멈춘 것 |
| 부하 구동, 범위 **안** 세 지점 | 0.03–0.04 mm | 평면은 부하에서도 건전 |
| 처짐 | 1.91 / 2.47–5.27 / 8.65 mm | **진짜 결함은 높이** |
| 정지 항등식 `kp·lead` 대 `qfrc_bias` | 잔차 ≤ 0.043 N·m | 리드가 무게를 내고 있다 |

범위 밖 목표를 결함으로 읽은 것은 **내 측정 실수**였고, 스펙 R111에 그대로 적었다. 같은 모양의
오독이 이 저장소에 이미 두 번 기록돼 있다(`approach_clearance`의 갇힌 턱).

## 증거

- **R111**: 일곱 방 20시드 전부 20/20(표는 spec), 격자 24/25·22/25, 두 격자에 `place` 실패 0,
  빠른 스위트 전량 통과. 방 하나라도 20/20에서 떨어지면 싣지 않는다 — 이번에 **세 번** 그 기준에
  걸려 되돌렸다(전향보상, 플래그 패치 두 형태).
- **R112**: 선언과 docstring이 어긋나면 실패하는 테스트(기계적 가드) + 실제 파일 감사.
- **R113**: 닫지 않는다. 다섯 항목 각각의 현재 상태가 spec에 적혀 있다.

## 위험

| 위험 | 어떻게 다뤘나 |
|---|---|
| 제어를 고치면 출하 방이 깨진다 (A8이 두 번, 오늘 세 번) | 매 시도마다 일곱 방을 재고, 깨지면 되돌렸다. 전향보상은 **측정만 남기고 폐기** |
| 플래그로 걷는 몸 논리를 패치하기 | 두 번 시도해 두 번 다른 방을 깼다. 그래서 **경로 교체**(`_lower_in_act` 일반화)로 갔다 |
| 적분 폭주 | 클램프 0.4 m·s + 설정점 변경 시 비우기, 둘 다 이유를 주석에 |
| 이득을 눈대중으로 | 0·1·3·10·30을 쓸어 평평해지는 첫 값을 골랐다 |
| "실물 가능"을 과장 | R113을 닫지 않고 다섯 항목으로 남겼다. 감사 테스트가 "깨끗한 task 0개"를 고정한다 |

## 실제로 지은 것 (계획과 달랐던 점)

- **중력 전향보상을 설계했고 폐기했다.** 처짐을 가장 잘 잡았지만(0.02 mm) 방 둘을 0/20으로 깼다.
- **걷는 몸 규칙을 플래그로 막으려 두 번 시도했다.** 첫 번째는 `fetch_the_steel`을, 다른 조합은
  `conveyor_triage`를 깼다. 세 번째에 경로 자체를 교체했고, 그때 일곱 방이 전부 돌아왔다.
- **"역기구학 재설계"라는 항목 이름이 틀렸다는 것을 측정으로 확인했다.** 평면 정상상태는 이미
  건전했다. 남은 것은 `grab`(도달)이고, 그것이 다음 목표 함수다.
