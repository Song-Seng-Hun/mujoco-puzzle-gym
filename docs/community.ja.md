# 部屋とポリシーを共有する

自作のパズル部屋はこのリポジトリにPRで送り、学習したポリシーはONNXファイルに変換して外部リンクで共有します。話し合いはGitHub Discussionsで行います。

## 受け付けるものと受け付けないもの

| 受け付けるもの | 受け付けないもの |
|---|---|
| 部屋ファイル`*.yaml`(1ファイル64 KB以下) | Pythonファイル、プラグイン部品 |
| フォルダの説明`README.md` | `*.pkl`、`*.zip`、チェックポイント、runフォルダ |
| ポリシーの外部リンク(ONNX) | リポジトリに直接置くポリシーファイル |

部屋ファイルにはコードを入れられません。YAMLは`yaml.safe_load`で読み、論理式は決められた演算だけを許すインタープリターで計算します。そのため、受け付けるものを部屋ファイルに限っています。

## 部屋を送る

1. リポジトリをフォークし、`community/rooms/<GitHubユーザー名>/`フォルダを作ります。サブフォルダは使いません。
2. 部屋ファイルと、必要なら`README.md`を入れます。見本は`community/rooms/Song-Seng-Hun/`にあります。
3. 送る前に自分で点検します。

   ```bash
   uv run mpg check --community --seeds 20 --json community/rooms/<名前>/<部屋>.yaml
   ```

   結果が`"ok": true`である必要があります。
4. PRを開きます。PRには自分のフォルダ`community/rooms/<自分の名前>/`の中のファイルだけを入れます。他の人のフォルダや`community/`の外のファイルが混ざるとCIが失敗します。CIはPRの中の検査コードで動くので、部屋のPRが検査コードも一緒に書き換えられないようにするためです。PRテンプレートのチェックリストを埋めてください。

PRが開かれると、CIジョブ`community`が変更された部屋ごとに同じ点検を実行します(1部屋10分、全体で30分)。すべて通ると、管理者が目を通してマージします。自動マージはしません。

## `--community`点検が拒否するもの

| 拒否 | 理由 |
|---|---|
| 部屋ファイルの`plugins`キー | プラグインモジュールはコードを実行します |
| 部屋ファイルのフォルダの外を指す`stages:`のパス | ほかの場所のファイルを読ませないためです |
| 組み込みではない部品の種類 | プラグイン部品にはコードのレビューが必要です |
| 部品64個超 | CIの時間と学習コストを抑えるためです |
| 部屋の一辺が10 mを超える | 同じ理由です |
| 文字マップの一辺が40マスを超える | 同じ理由です |

`--community`は`--task`と一緒に使えません。taskファイルの`plugins:`がコードを読み込めるためです。点検は組み込みのtaskで行います。

## ポリシーを共有する (ONNX)

ポリシーはリポジトリに置きません。代わりにONNXに変換してHugging Faceなどにアップロードし、Discussionsの`Rooms`カテゴリーにリンクを残します。

```bash
uv pip install 'mujoco-puzzle-gym[export]'
uv run mpg export-onnx runs/<id>
```

`runs/<id>/onnx/`に二つのファイルができます。

- `policy.onnx`: 決定的な行動を出すポリシーのニューラルネットワーク
- `policy.json`: 観測の項目とサイズ、行動の範囲、学習したtaskのSHA256、部屋の名前

書き出せるのはベクトル観測のポリシー(PPO、A2C、SAC)だけです。カメラ観測のポリシーにはまだ対応していません。

受け取ったポリシーはpickleを使わずに評価します。二つのファイルを同じフォルダに置き、そのポリシーを学習した部屋を使う自分のtaskファイルを`--task`で渡します。

```bash
uv run mpg eval --onnx policy.onnx --task task.yaml --episodes 100
```

観測のサイズや行動のサイズがtaskと違うと、評価を拒否します。サイズは同じでも観測の項目が違うと、結果に`warnings`が付きます。

## 他人のrunフォルダやpklを開かないでください

SB3のチェックポイント(`checkpoint.zip`)、チェックポイントの保存ファイル(`*.pkl`)、runフォルダの`task.resolved.yaml`は、開くときにコードを実行できます。そのため`mpg`はこれらのファイルを、現在のフォルダの`runs/`の下と、リポジトリに同梱のデモからだけ読みます。それ以外のパスは理由を示して拒否します。

自分で作ったファイルを別の場所に移したときだけ`--trust`を付けます(`train`、`eval`、`diagnose`、`render`、`export-onnx`)。`--trust`はそのコマンドの実行中だけ環境変数`MPG_TRUST=1`をオンにします。シェルでこの変数を常にオンにしておくとパスの検査が切れたままになるので、そうしないでください。
